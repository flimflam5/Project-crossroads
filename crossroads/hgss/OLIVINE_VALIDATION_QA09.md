# Olivine reconstruction validation changes

The previous48×48 Olivine assertions describe a temporary blockout with two
short piers. They cannot certify the canonical64×64 city, three additional homes,
café, port terminal/quays or branched lighthouse. The reconstruction activates
the independent `validate_hgss_olivine.py` path only when its explicit authoring
contract exists; the complete historical checker remains available otherwise.

The replacement pins canonical entrance coordinates from the actual HGSS event
data, every original doorway destination/ordinal, all existing city configuration,
actor/script identities, exact added building signs, dry pedestrian approaches,
both outside/inside door leaves and safe Center arrivals. Existing map groups,
map ordinals, layout ordinals and heal IDs remain prefix-stable against delivered
`fd151242458efe5759b18650f35a5e5b2fa47e45`. All other heal entries remain unchanged.
Olivine's one existing heal entry changes only its position to16,34 and nurse
arrival to8,13. The office rescue object remains4,4 with its original script.

Six old workstation ceiling-cap tiles were isolated passable floor above a solid
wall: Silph1/2/7/8,0 and Harbor7/8,0. The generator now adds only collision0x400
to those six words. Every metatile ID, displayed pixel, other tile, interior actor,
interaction and warp remains exact. The strengthened office check independently
requires every public dry tile to reach the exits. This prevents an obsolete save
from being relocated onto an isolated ceiling. Cafe's source staff alcove has a
single explicit GBA service-side opening at12,8, with its counter still solid;
the every-tile graph has no special exemption for it.

The global validator's blanket fixed-reciprocal-warp assumption is replaced only
for the independently enumerated native elevator leaves and source4F window.
`hgss_olivine_validation.py` requires the actual source-to-native stair coordinates,
paired lift mouths, two accessible floor panels, real `setdynamicwarp` targets,
floor return initialization, exact one-way window script and balcony return path.
It then requires all canonical exits/interactions to be reachable and escape from
every public interior tile. Generic single-room flood checks are skipped only
after this stronger directed graph has passed. The source window is an intentional
HGSS one-way drop; no arbitrary missing reciprocal warp is exempted.

The historical Ecruteak validators retain their pixel, layer, behavior and source
geometry assertions. Legitimate Olivine additions append exactly nine map names.
Route39/40 changes are bounded to exact connection offsets, primary buffer pointers,
seven-tile seam paving aliases and the western five-row land aperture; remaining
route metadata/terrain is pinned to the prior delivered revision. No accepted
Ecruteak field, shared native service layout or other city is broadly ignored.

`Crossroads_EnsureAreaRespawn` migrates only the exact old Olivine11,22 heal warp.
`NeedsDryLanding` now covers Olivine waterfront as well as Violet's pond, using
the same saved graphics byte order as the engine. Actual Joe/Brendan/May Surf
saves are preserved; old walking saves newly over water move to clear dry ground.
No saved structure, flag allocation, item/Pokémon data or map ID changes.

The new `olivine_save_smoke.py` uses copied batteries, actual menu Save and cold
title/Continue. Normal Center/home/Surf cases use controller movement. Explicit
legacy fixtures alone seed obsolete XY, heal or cached-layout values in private
RAM before a normal Save. Party, boxes, starter, money, coins, PC items, registered
gear, all bag slots and flags must persist. Money/quantities are compared after
decoding the engine's legitimately rotated encryption key, rather than accepting
or incorrectly failing changed ciphertext. The original input battery is hashed
before and after and must remain unchanged. ROM checksum accompanies the results.
Normal save coverage includes all nine appended interiors/landmark maps and the
isolated southern3F and top6F lighthouse sections, with an actual walk-away,
door/stair exit and return after Continue. Separate cabin cases select1F and6F
through the real panels, then save/cold-boot and verify the actual exit floor.

On the delivered QA08B2 layout, none of the historical walking cells becomes
water. The new test reports that fact and exercises the defensive walking-water
guard with a separately labelled synthetic shoreline position; it does not
misrepresent that coordinate as an old walkable cell. Actual Surf retention and
a genuine historical walking position now inside a wall are separate cases.

Normal controller testing exposed a port forecourt return trap that the earlier
plain-floor flood missed: it counted active door thresholds as walking paths.
Every outside arrival must now reach the Center apron on dry ground without
crossing any active threshold. The failing V5 case was independently reproduced
from its actual compiled ROM map bytes, preserving its checksum/evidence. The
east-side boardwalk repair must pass the same assertion and real return journey.
The post-build Olivine validator also compares all24 compiled map blockdata
symbols against authored outputs, detecting stale layouts after regeneration.

The definitions above accompany the actual delivery results and native recordings.
Compilation, structural checks, controller-driven gameplay and owner Delta review
are reported separately.
